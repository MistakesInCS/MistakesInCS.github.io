## Introduction

I read in a textbook once that mislabeling examples can help detect overfitting; when the network achieves good training loss on the mislabeled examples, it's likely that it is beginning to memorize the training set instead of learning to generalize. Later on, I misremembed this part as implying that mislabeling examples can help improve generalization. That's a little bit different! But it made for some interesting thoughts. Could noise actually be a good thing? It seems counter-intuitive to how humans learn - everytime I ran into incorrectly solved problems in school, I would get upset and begin to question my methods. Humans seem to learn better with very clear signals that reward consistency and detailed feedback, and so intuition is established that all learning must be this way. But learning for a neural network is moreso like optimization. As far as I'm aware, humans don't learn by gradient descent, and it's impossible for a human to reasonably work through datasets of tens of thousands of examples for multiple epochs. 

Perhaps, then, noise works for metal where it fails for flesh.

## Noise as Addition

Of course, without intentionally adding noise into the training process, the only noise that could exist naturally is from the minibatch nature of training. Since each parameter update only considers a minibatch of the training examples rather than the entire dataset, there is almost certainly some deviation in the minibatch's average gradient from that of the dataset's. 

This noise could be modeled as a small vector added to the gradient during the update. Note, however, that the distribution this noise is sampled from is unique, since its source is the set of all minibatches at that point. This is absolutely not guaranteed to be uniform in any way. It is possible for the minibatches to all have similar gradients at that point; this is a potential low variance region of the surface where each minibatch (and probably each example) matches the overall loss surface. Likewise, it is possible for minibatches to have wildly different gradients in a high-variance zone. 

As an aside, I don't think that low-variance areas necessarily imply good generalization. The "shape" of the loss surface could be the same for many different minibatches, while their offsets and loss scores could vary significantly. However, I do think that high-variance areas do imply poor generalization, since a "good vector" existing for one minibatch and not for another would likely lead to overfitting to that minibatch at the expense of the other. 

I considered noise as a kind of simulated annealing, allowing for a larger set of potential "moves" to make that would allow the model to potentially escape local optima in the overall surface, but this would only work for areas with high enough variance to allow for a large enough set of gradients. In a low-variance region, all the minibatches would "agree" on the gradients, and so local optima would be inescapable, since every minibatch would also have that optima.

Because minibatches have a varying distribution of gradients, I figured that adding a more uniformly distributed noise vector would allow for a larger potential set of gradients, regardless of minibatch variance. 

Before I made that realization, however, I wanted to make sure that my idea would work.

## A Literal Surface

To start with, I wanted to get a visualization of the loss surface and the parameters moving through it. It's basically impossible to visualize higher dimensions, so I started small. I wanted to make a small network with just two parameters to optimize. Unfortunately, a network with just two parameters doesn't have very interesting optimization surfaces. For an MLP, for instance, two parameters is two weights, which isn't very interesting without biases, or a weight and a bias, which is just a line, or two biases, which also isn't interesting. 

Then I stopped being stupid and realized that I didn't need a model or data in order to create a loss surface. I could simply make the surface manually, and use the coordinates of that surface as the parameters to be optimized. This is much simpler than trying to create the perfect model and training data that look nice.

I envisioned the noise as "ripples" along some "canonical" original surface; each point would be moved up or down randomly. To make this happen, I chose a random point on the surface to act as the center of some sin wave that would be added to each point. This has the effect of adding a random gradient from the set of sin wave gradients to the loss gradient at that point. If that doesn't make sense, just imagine ripples through the surface pushing the parameters around.

I optimized two parameters on the loss surface using this method and the Adam optimizer and recoded their path. Here is a visualization:

![Path taken by perturbed weights](/assets/noise/bowl1.png){: normal}

Which is great and all. The parameters eventually get out of the small optimia and into the better one, but they don't settle into a good spot. This is probably fixed by lowering the amplitude of the sin waves over time, like in simulated annealing.

But then I made a realization: if you add a random gradient vector to the gradient, it's the same mathematically as adding a random vector directly to the parameters. The only difference is that, with minibatching, the random vectors come from the minibatch's set of gradients; with "rippling" sin waves, the random vectors come from the set of sin wave gradients; and with directly random vectors, you're completely free to decide the set to be sampled from.

At this point, I had started to do some research, and Gemini had mentioned [Sharpness Aware Minimization](https://arxiv.org/abs/2010.01412), which is very interesting but ultimately unrelated; SAM is about picking better gradients within some neighborhood of the parameters, while I'm interesting in adding some amount of noise. This did, however, inspire me to wonder whether or not *keeping* the noise was worthwhile, or if it's better to restore the original weights and just use the "noisy" gradient. Also, apparently this is called *weight perturbation*, so from now I'll use that term.

I couldn't come up with an argument to prove that one or the other was strictly better - keeping the noised parameters risked turning the update sequence into a random walk, but it could be easier for it to escape local optima thanks to the additional movement conferred by the noise. Restoring the original parameters is almost a completely different process; instead of adding noise to the parameters, the process essentially replaces the traditional gradient update with a *gradient neighborhood* update, where the gradients are sampled from nearby points rather than exclusively the point of the parameters. 

For my first tests, I again used the loss surface and parameters with Adam:

![Path taken by perturbed weights, additive noise, kept](/assets/noise/bowl2.png){: normal}
![Path taken by perturbed weights, additive noise, originals weights restored](/assets/noise/bowl3.png){: normal}
_Left: additive noise, with the noise kept by the parameters each update. Right: additive noise, but the original, pre-noised parameters are restored, and the gradient from the noised parameters is used instead._

On the left, I added noise to the parameters each update. It shakes around a little in the local optima, but it eventually escapes and rests in the global one. On the right, I added noise to the parameters, took the gradient, but added the noised parameters' gradient to the original, pre-noise parameters. It spends no time in the local optima and heads straight to the global one. I think this incredible performance is not due to the potential superiority of the method, however, and rather can be attributed to an oversight: I made the length of the noise vector fixed, while the direction was random. The length of the noise vector is likely too large for the local optima, so while the parameters that kept the noise would be moved, fall back down, moved again, the parameters that restored the original weights would simply "look past" the local optimum to the greater bowl outside it, ignoring the local optimum completely.

## MNIST

Toy problems with three dimensions are nice, but there are many more variables to be encountered with scale and complexity. To crank up the scale, I decided to train on MNIST. Since fixed-length noise vectors created the issue above, I wanted to use variable lengths, but that begs the question of how to sample them. I decided on two methods: uniformly and from a beta distribution (alpha = 1.5, beta = 3), which I subjectively descided had a nice skew to it - I figured that a distribution that favored shorter lengths and nearer points would be "more informative" than a distribution that allowed for further points. As such, I decided on 5 networks: a control, two networks where the noise is kept, and two networks where the original, pre-noise weights are restored. For the non-control networks, one each from the categories would sample the length uniformly, while the other would sample from the beta distribution.

While I had no expectation on how keeping vs discarding the noise would perform, I did have a hypothesis regarding the length distribution. At the extreme, a large enough length interval results in randomly sampling gradients from the entire loss surface, which completely prevents convergence and optimization, so if the lengths were biased towards lower values and nearer points, the network would still sample mostly nearby points while allowing it the potential to sample further points that could let it escape local optima. 

For some optima, there exists a region around it that if the parameters were to enter, they would be unable to leave. Let's call this area the "event horizon" of an optima. By allowing gradients to be sampled from the parameters' neighborhood, regions close to the edge of the event horizon can escape by sampling gradients from outside of it. This effectively shrinks the event horizons of all local optima. Actually, as seen above, there may be local optima that lose their event horizons altogether. For this reason, I expect the networks that use weight perturbation to achieve better results than the control.

I eventually figure that it must be the weight decay in AdamW. Weight decay has the effect of simply subracting the parameter vector (with a small constant) from the parameters; as a result, any additive noise is slowly subtracted away from the parameter vector over time, lessening its effect. I think this generalizes, such that weight decay stabilizes additive noise *in general*, and weight decay also reduces the impact of additive functions on the loss *in general*. A very interesting conclusion!

Now we see the first interesting pattern to emerge. The non-uniform length sampling actually has some shakiness to it! This is contrary to my hypothesis that the non-uniform sampling method would be superior to the uniform one. This holds throughout all the other experiments. I think the cause is that uniform sampling results in a "better" expected value of the nearby gradients. My first thought is that the distributions act as kernels, smoothing out the effective loss surface of the expected gradients. The uniform distribution, taking a strict arithmetic mean, results in a much smoother surface than the beta distribution, which acts like a weighted mean, retaining the noise and sharpness of some areas over others. My second thought is that the most "relevant" gradients are closer to the actual parameters, but the beta distribution actually has a *lower* probability of closer lengths than the uniform ditribution despite having a lower expected value! This means that high-relevance, low-distance lengths are being ignored in the non-uniform distribution, while in the uniform distribution they balance out the low-relevance, high-distance lengths.

Another possibility is that the uniform sampling method tends to find flatter, smoother areas where the gradients don't vary as much, similarly to shaprness-aware minimization. But I don't really believe that one over the previous reasoning.

## Other Research

The point of this experiment was to see what I could discover and reason about on my own, and then compare my results to those in existing literature, found by people much smarter than me. 

In ["Adding Gradient Noise Improves Learning for Very Deep Networks,"](https://arxiv.org/pdf/1511.06807) the authors end up with a pretty similar setup, adding a Gaussian noise vector to the gradient each update, which is similar to my keep models, but with a different length distribution. They also anneal the weight over time, as I did in my final experiment. However, they use SGD without momentum, and a deep network of 20 layers with 50 units each layer. I used Adam as my optimizer, and my network was a liiiiittle bit bigger - I used the MLP used in the pytorch quickstart, which has just under 700,000 parameters before counting biases, while the paper's has only around 50,000 before biases (to be fair, this paper is 10 years old - it mentions LSTM networks as recent). The authors find universal improvement in all the models they trained. Perhaps this is due to the choice of optimizer - SGD is very susceptible to local minima, while adding momentum can let it escape a lot of small ones. That would be a cool ablation, to compare how much noise improves results to the choice of optimizer. As seen before, AdamW (and any L2 regularization/weight decay) negates a lot of the shakiness of noise.

The grokking paper (https://arxiv.org/pdf/2201.02177) has some graphs showing training with noise, but it had a negative effect.

And I am noticing now that my strategy of reading citations for more papers to read only works for going backwards in time. 

Gemini pointed me to this paper, ["Understanding the Generalization of Stochastic Gradient Adam in Learning Neural Networks"](https://arxiv.org/abs/2510.11354). It said, "This paper provides a theoretical characterization of how stochasticity in the Adam optimizer prevents it from overfitting "noise patches" in training data." Which is true. However, then it says, "It argues that the noise in mini-batch gradients slows down the fitting of noise while preserving feature learning," which I don't think is true. I think the paper more directly argues that the model, when using large batches, is exposed to more consistent and complete pictures of the noise, allowing it to better learn the noise and overfit the training set; when using small batches, each update has a smaller portion of the noise of the dataset. The larger batches have a higher noise/feature ratio, while the smaller batches do not. While this could technically be considered "noise" in the smaller batches, I think it's more accurate to say that there is actually less noise in the smaller batches since the model can't fit it as well.

When you think about it, dropout is also like adding a noise vector to a layer, since deactivating a neuron is like subtracting some amount from that parameter. The difference is again the distribution of vectors: instead of being uniform, the possible vectors are tied very closely to the current parameters.

This paper, ["Enhancing Exploration in Global Optimization by Noise Injection in the Probability Measures Space"](arxiv.org/pdf/2601.22753) seems to be exactly what I'm looking for. Unfortunately, I can't understand any of the math! My big takeaway is that there are optimization algorithms inspired by Langevin dynamics that include noise in their update. Trying to learn more about Langevin dynamics, I read this paper on an optimization method the authors call Coolmomentum (https://www.nature.com/articles/s41598-021-90144-3), which is essentially SGD with momentum using specially decaying momentum factors and learning rates. I have some gripes with this! I of course do not have the mathematical or physical knowledge that the authors have, but I can't seem to find real numerical data for their results. The authors claim that Coolmomentum outperforms the other models ("One can see that in this case Coolmomentum also achieves the top results."), but only provide figures for comparison between models. The only numerical data provided are for comparing results between hyperparameters of the Coolmomentum optimizer. Looking at the figures, it isn't obvious that Coolmomentum is the top performer; honestly, it only seems to outperform the others in training loss on Cifar-10. For all the other figures, if you zoom in, it actually looks like the other models/optimizers are performing better. This makes it very difficult to accept the authors at their word that their technique actually worked better. Additionally, although my understanding of both subjects is poor, I think that a difference between minibatch noise and Langevin noise is that minibatch noise is likely not stationary, since while its expected value is 0, the variance of minibatch gradients likely change over time as the parameters move. An area of good generalization likely has similar gradients between minibatches (small, pointing to a flat minima, consistent b/w batches), while an area of overfitting might have large variance (potentially large, pointing to local per-batch minima, otherwise pointing away from non-fit batches). Further, I fail to see the similarity to simulated annealing beyond a decaying temperature hyperparameter, which already exists through schedulers. The defining element of SA for me is the additional exploration from taking suboptimal parameter choices; since it looks like the only difference between CM and SGD with momentum is the decaying hyperparameter, I don't see how CM is any more or less like SA - the gradient choices in both are, essentially, the same, and the difference is in how much of it is added to the momentum.

An additional area to inject noise that I forgot about is in the input. The textbook I read talked about regularizing by manipulating input images; flipping them, changing their colors, cropping, etc.

## Conclusion

I think that, in a very favorable interpretation, adding noise directly to parameters is ineffectual with modern techniques. Perhaps there is a situation that treats this method more favorably, but there are already so many different little tricks and optimizations that this would likely be an additional performance cost for a poor performance gain. I don't know what the updates for billion dollar AI models look like, but they likely have so many parts that adding noise would probably result in poorer results as a start, already have its purpose covered by some other part, and interfere with something else.

As a more practical recommendation, perhaps more noise can be injected by simply lowering the batch size. As that paper I mentioned earlier showed, a small batch size with Adam can be more beneficial anyway. The variance of the noise can be lowered as training continues by increasing the batch size. Having a smaller batch size at the start can also free up resources for other processes, potentially costlier updates or training multiple models in parallel for ensemble learning.

All that noise I made got silenced by AdamW anyway, so weight decay likely makes this all moot.
